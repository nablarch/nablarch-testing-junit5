## Method（検証方法の適用確認）

- 実行コマンド: `mvn -o clean test`（フルスイート、EXIT=1）/ `mvn -o clean test -Dtest=TestRuleEmulationIntegrationTest -DfailIfNoSpecifiedTests=false`（単体、EXIT=1、`Tests run: 3, Failures: 3`）。いずれも失敗内容は同一の実行順違反。
- 3 件が独立に報告されること: `.txt` / `.xml` の両方を実際に開いて確認。`.txt` は `テストメソッドの実行がTestRuleに包まれていることをテスト` / `パラメータ化テストの実行がTestRuleに包まれていることをテスト{int}[1]` / `同[2]` の 3 ブロック、`.xml` は同名の `<testcase>` が 3 件でいずれも `<failure>` 付き。`@AfterAll` によるクラスレベルの失敗ケースは消えたため、フルスイートの総数は 35 → 34 に減った（失敗は 1 → 3）。
- 既存テストへの影響なし: フルスイート 34 件のうち失敗は本テストの 3 件のみ。`TestEventDispatcherExtensionTest`（10 件）、`TestEventDispatcherExtensionLifecycleMethodTest`、`TestEventDispatcherExtensionIntegrationTest` を含む他の全テストは成功。
- 実行ログの持ち越しがないこと: 3 回のテストメソッド実行それぞれのログが 5 要素（`[outer-before, inner-before, inner-after, outer-after, test]`）で、連結していない。ログは `RecordingSupport` のインスタンスフィールド（`TestRuleEmulationIntegrationTest.java:103`）であり、テストインスタンスごとに新しくなる。記録用のコレクションは `Collections.synchronizedList` / `Collections.synchronizedSet` で包んである（`:103-104`）ため、別スレッドから書かれた場合でも `@AfterEach` 側からその書き込みが見える。
- ルールの入れ子順の導出: JUnit 4 の `org.junit.rules.RunRules`（`junit-4.13.1-sources.jar` の `org/junit/rules/RunRules.java` を展開して確認）は、コンストラクタから呼ぶ `applyAll` で `for (TestRule each : rules) { result = each.apply(result, description); }` とリスト順に適用していく。すなわち**リストの末尾にあるルールほど最外側**になるのが JUnit 4 側の契約であり、`TestEventDispatcherExtension` の再現もこれに従う。よって `inner` → `outer` の順に追加したとき、期待される実行順は `outer-before, inner-before, test, inner-after, outer-after` となる。
- 同一スレッド表明が空回りしていないこと: 記録を別スレッド（`probe-thread`）で行い、かつスレッドの表明を先に評価するようにしたプローブを一時的に当てて `mvn -o clean test -Dtest=TestRuleEmulationIntegrationTest` を実行した。結果は `Tests run: 3, Failures: 3` で、3 件とも失敗内容が `Expected: is <[Thread[#1,main,5,main]]> but: was <[Thread[#27,probe-thread,5,], ...]>` のスレッド表明の不一致になった。すなわちこの表明は実際に評価され、テストを実行しているスレッド以外で記録が行われた場合に落ちる。同時に、記録を `Thread` インスタンスの集合で持つことで同名スレッド 5 本が 5 要素として現れており、スレッド名の集合で持っていた場合に単元集合となって素通りする穴がふさがれていることも確認できた。プローブは確認後に削除済み（`git diff` に残っていない）。
- カバレッジ計測手段: **あり**。親 POM（`com.nablarch:nablarch-parent`）が jacoco-maven-plugin 0.8.8 をオフライン instrument モードで設定している。`report` ゴールは束縛されていないため、`mvn -o jacoco:restore-instrumented-classes jacoco:report -Djacoco.dataFile=$PWD/jacoco.exec` を手動で実行して計測した。`jacoco.exec` は追記されるため、フルスイート／単体それぞれの計測前に削除して取り直している（計測後、リポジトリルートの `jacoco.exec` は削除済み）。
