### `interceptTestMethod` / `interceptTestTemplateMethod` を `final` にした

Design レビューの実測により、利用者の Extension がこの 2 メソッドを自分で override すると
`resolveTestRules()` が返したルールが**何のエラーも起こさずに消える**ことが分かったため、
2 メソッドを `final` にした（`TestEventDispatcherExtension.java:155,177`）。
該当する利用者はコンパイルエラーで気づける。今回新設したメソッドなので互換上の損失はない。
代替手段（`InvocationInterceptor` を実装した別の Extension クラスを作る）は Javadoc に明記した（`:146-147`）。
`src/main` で `final` を付けたのはこの 2 メソッドだけである。
あわせて 2 メソッドの同一の本体を `private invokeWrappedInTestRules(Invocation, ExtensionContext)`（`:193-196`）へ括り出し、
どちらも `ReflectiveInvocationContext` を使わないことを引数の形で示した。

### `JupiterEngineRunner` を `junit-platform-launcher` ベースへ置き換えた

置き換え前は `org.junit.jupiter.engine.JupiterTestEngine`（`@API(status = INTERNAL, since = "5.0")`）を直接使い、
`EngineDiscoveryRequest` / `ConfigurationParameters` / `EngineExecutionListener` を自前で実装していた。
テストインフラが JUnit の内部 API に依存する状態だったため、STABLE な `LauncherFactory` +
`LauncherDiscoveryRequestBuilder` + `SummaryGeneratingListener` に置き換えた。
`pom.xml:70-75` に `junit-platform-launcher`（test スコープ。バージョンは `junit-bom` 由来）を追加している。
**183 行 → 141 行**（`ExecutionSummary` は薄いアダプタとして残したので呼び出し側は変えていない）。

**surefire 2.22.2 との衝突は起きなかった。** 置き換え直後の `mvn -o clean test` が
`Tests run: 55, Failures: 0` / `BUILD SUCCESS` で、オフライン解決も失敗していない
（`~/.m2/repository/org/junit/platform/junit-platform-launcher/1.11.0` が存在する）。

`SummaryGeneratingListener` は失敗・中断・スキップを分けて持つので、`ExecutionSummary` にも
`getSuccessfulTestCount()` / `getAbortedTestCount()` / `getSkippedTestCount()` を持たせた
（`JupiterEngineRunner.java:82-114`）。置き換え前の `RecordingListener` は ABORTED の `Throwable` も
`failures` に混ぜており、`@Disabled` なフィクスチャは `count=0 failures=[]` と黙って 0 件成功扱いになっていた。
置き換え後の値を使い捨ての probe で実測すると次のとおりで、成功と区別できている。

```
### disabled : started=0 ok=0 aborted=0 skipped=1 failures=[]
### aborted  : started=1 ok=0 aborted=1 skipped=0 failures=[]
```

これを受けて、「すべて成功した」ことを表明していた箇所は
`assertThat(summary.getFailures(), is(Collections.emptyList()))` から
`assertThat(summary.getSuccessfulTestCount(), is(1))` に置き換えた。中断もスキップも成功とは数えられない。
**この probe はコミットしていない**（実行後に削除。`git status` で確認済み）。

### テストコードの整理

- 3 クラスに重複していた「`static final List<String> executionLog` ＋ `@BeforeEach` の clear ＋ `@AfterEach` の
  `clearTestRules()`」を、同パッケージの package-private な `RuleIntegrationTestBase`
  （`src/test/java/nablarch/test/junit5/extension/event/RuleIntegrationTestBase.java`）へ寄せた。
  2 クラスで同一だった `RecordingTestFixture` もここに置いた（`:60-65`）。
  `TimeoutRuleIntegrationTest` を含む 5 クラスがこれを継承する
- 2 クラスでほぼ同一だった `RecordingRule` を package-private な top-level クラス
  （`src/test/java/nablarch/test/junit5/extension/event/RecordingRule.java`）に切り出した。
